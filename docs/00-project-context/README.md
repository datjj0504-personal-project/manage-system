# Project Context

This folder contains the baseline context required before making architecture, implementation, or documentation changes in the repository.

## Documents

- `overview.md`: Project objective, learning goals, and high-level direction.
- `business-domain.md`: Core business objects, responsibilities, rules, and future extensions.
- `glossary.md`: Shared terminology used across documentation and implementation.
- `tech-stack.md`: Selected technologies for backend, frontend, and development workflow.
- `coding-principles.md`: Core engineering principles and layer expectations.
- `decision-log.md`: Architecture Decision Records and key technical choices.
- `non-functional-requirements.md`: Quality requirements for performance, security, reliability, maintainability, and operations.

## How To Use This Folder

- Read `overview.md` first for project direction.
- Read `business-domain.md` and `glossary.md` before defining API or database changes.
- Read `coding-principles.md` and `decision-log.md` before making architecture decisions.
- Read `non-functional-requirements.md` when evaluating production-readiness concerns.

## Maintenance Rules

- Keep terminology consistent with `glossary.md`.
- Update related documents together when business rules or architecture change.
- Record new architecture decisions in `decision-log.md` instead of rewriting history.
