# Commit Rules

## Allowed Types

- feat
- fix
- refactor
- style
- docs
- test
- build
- ci
- perf
- chore

## Commit Message Format

`[Type]: Short imperative summary`

Examples:

- `[feat]: Implement auth login endpoint`
- `[fix]: Handle null assignee in task mapping`
- `[docs]: Update API contract for user profile`

## Rules

- Keep one logical change per commit.
- Keep summary concise and specific.
- Avoid vague messages such as `update` or `add` without context.
- Reference issue or ticket in body when applicable.
