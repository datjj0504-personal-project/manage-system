# Automation Runner

## Purpose

This folder contains Windows batch scripts that let a developer execute the backend test suite from the `backend` directory with a single command.

The current backend automation coverage includes:

- Unit tests
- API tests

Integration tests are not present yet, so the integration runner skips gracefully.

## Available Scripts

### `run-all.bat`

Runs the complete backend test suite with `mvn test`.

### `run-unit.bat`

Runs only the service-oriented unit tests by matching `*ServiceImplTest`.

### `run-api.bat`

Runs only the API tests by matching `*ControllerApiTest`.

### `run-integration.bat`

Checks for integration coverage and currently skips because no integration tests exist yet.

### `clean-and-run.bat`

Cleans the backend target directory and runs the full test suite with `mvn clean test`.

### `generate-report.bat`

Runs the suite and attempts to generate Surefire HTML output. If Failsafe reports exist later, it also attempts the Failsafe HTML report.

## How To Run

From the `backend` directory:

```bat
automation\run-all.bat
```

Or run a specific category:

```bat
automation\run-unit.bat
automation\run-api.bat
automation\run-integration.bat
automation\clean-and-run.bat
automation\generate-report.bat
```

## Expected Result

- `PASS`: the Maven command finishes with exit code `0` and the script prints `SUCCESS`.
- `FAIL`: Maven returns a non-zero exit code and the script prints `FAILED`.
- `Skipped Tests`: the integration runner will report that no integration tests were detected.
- `Generated Reports`: Surefire XML reports are produced under `backend/target/surefire-reports` after test runs. HTML output is generated when the report goal succeeds.
- `Exit Codes`: `0` for success, `1` for failure.

## Troubleshooting

- Missing `JAVA_HOME`: install JDK 21 and ensure `java -version` works in a new terminal.
- Missing Maven: use the Maven wrapper from the backend root; do not rely on a global Maven install.
- Database unavailable: future integration tests may require PostgreSQL on `localhost:5432`.
- Spring profile mismatch: the scripts print the active Spring profile; update `SPRING_PROFILES_ACTIVE` if a test needs a different profile.
- Port already in use: stop conflicting services before starting backend-dependent tests.
- Test failures: read the console output and the XML report under `target/surefire-reports`.
- Permission denied: run the batch files from a shell with access to the repository path.

## Reporting Notes

- JUnit XML and Surefire XML are generated by the standard Maven test lifecycle.
- HTML reporting is not configured in the current `pom.xml`.
- If you want richer HTML reports later, add `maven-surefire-report-plugin` and, for integration tests, `maven-failsafe-report-plugin` to the backend build.
